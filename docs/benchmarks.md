# dsh-policy 基准报告解读（Stage 16，计划书 Phase 18）

> 数据来源：`pnpm bench`（`bench/run.ts`）→ `bench/report.json`。方法 = 真实 Harness 栈上的确定性回放（ScriptedAdapter 是唯一 mock，零本地推理）。
> 本文件的表格记录 2026-09-03 基准跑（Windows 11 / Node 24 / 本地）。速率类指标是**确定性的**并由 `tests/integration/bench.test.ts` 钉死；延迟类指标随环境浮动，只报告不断言。

## 1. 约束有效性（36 例 = 规则数 1/2/4 × 噪声 0/3/8 × 4 类案例）

| 指标 | 结果 | 含义 |
|---|---|---|
| 违规检出率 | **100%**（18/18） | 缺测试 / 测试失败两类违规全部被 turn-stopping 拒绝 |
| 误拦截率 | **0%**（0/18） | 合规回合与无改动回合全部正常完成 |
| 误放行率 | **0%**（0/18） | 没有任何违规回合被静默放行 |
| 补救成功率 | **100%**（3/3） | 拒绝 → 注入补救 → 补跑验证 → 放行，全链成功 |
| 完成正确性 | **100%**（36/36） | 每一例的实际结束与预期一致 |

矩阵覆盖了规则数量（1/2/4 条硬规则）与噪声工具调用（0/3/8 次）两个维度，证明强制与案例长度、规则数量无关。

**基准发现并修复了一个真实缺陷**：首轮全量矩阵跑出 5.6% 误拦截（1/18）——`EvidenceRecorder` 用毫秒级 `Date.now()`，快速内存栈上"改代码"与"通过测试"落进同一毫秒，引擎的严格大于比较把通过测试误判为改动前证据 → 误 BLOCK。修复：记录时保证逻辑时间戳严格递增（因果序），回归测试钉死（`tests/unit/policy-engine.test.ts` "same-millisecond evidence stays causally ordered"）。这正是计划书 Phase 18"用基准证明有用而非装饰"的价值：装饰性指标发现不了这种间歇性缺陷。

## 2. 个性化有效性（机制的确定性代理指标）

| 指标 | 结果 | 说明 |
|---|---|---|
| 偏好相关性精确率 | **100%**（16/16 矩阵格） | 相关任务注入、无关任务零注入（language/glob/taskRegex/无条件四类 × 4 任务画像） |
| 偏好相关性召回率 | **100%** | 应注入的全部注入 |
| Guard 提醒送达率 | **100%**（5/5） | 匹配工具的每次执行后，提醒都进入下一请求 |

**诚实边界**："模型是否遵循提醒/偏好"（adherence）无法用脚本适配器度量——那需要真实模型行为，属推迟的云端 e2e（Stage 15 已登记）。本报告钉死的是**机制层**：送达、精度、召回、持久化（接受→持久、拒绝→墓碑不复活，由 Stage 10/12 测试套件覆盖）。

## 3. 成本（硬指标）

| 指标 | 结果 | 说明 |
|---|---|---|
| 每请求 prompt 增量 | mean **346** / p50 **315** / p95 **491** tokens | 运行时上下文快照随每个请求重发；随硬规则数线性增长（1 条 ≈ 200，4 条 ≈ 500） |
| 钩子延迟（墙钟差） | p50 **0.25ms** / p95 **0.73ms** | 有插件 vs 无插件完成同一脚本回合的墙钟差（P50/P95，n=20） |
| `evaluateTurn` 纯评估 | **≈5.2µs/次**（100 事件 × 2 规则，5000 次平均） | 约束评估不构成任何可感知延迟 |
| 证据追加 | **≈0.48ms/条**（持久 JSONL）；96KB/会话文件（500 条） | 同步 fs 是已登记的 MVP 取舍 |
| **额外 LLM 调用** | **0**（全部合规/无改动回合，矩阵级断言） | 计划书"零额外 LLM 调用 MVP"的硬断言；违规回合的补救调用是设计行为（+2 预算内） |

## 4. 方法与局限

- **确定性**：脚本适配器回放固定响应，速率类结果可精确复现；`report.json` 的 meta 记录环境。
- **延迟口径**：以"同脚本回合的墙钟差"为钩子开销（对用户可感知的量）；不直接插桩 harness 内部。
- **未覆盖**（诚实登记）：真实云端回合的端到端成本与模型遵循率（依赖 DeepSeek key，部署期验证）；多会话并发下的存储竞争（单进程假设）。

## 5. 结论

计划书 Phase 18 的三个维度全部量化达标：约束强制**零误报零漏报**（36 例矩阵）、个性化机制**满精度满召回满送达**、成本为**每请求约 350 tokens 的可解释线性开销 + 亚毫秒钩子延迟 + 零额外模型调用**。项目"有用而非装饰"的主张首次有了可复现的数字支撑。
